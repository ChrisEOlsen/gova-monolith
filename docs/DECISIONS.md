# Decisions

Why a few things are shaped the way they are. Source comments point here rather
than carrying the argument inline.

---

## 1. Auth is committed code, not a scaffold

Auth used to be generated by a `scaffold_auth` tool from seventeen templates.
That made it text, and text cannot be compiled — so a separate test rendered the
templates into a fixture tree and ran `go build` over the result, and a whole
credential-classification subsystem existed in the generator so that *generic
CRUD* could be trusted near a password column.

Shipping auth as ordinary Go in `src/app` removes all of it: `go test ./...` is
the compile gate, and the scaffolding commands simply refuse credential columns
(`src/builder/schema.go`) because they have no business near one.

The manifest still describes auth — `src/app/api.json` ships pre-populated with
the user model, the eight auth endpoints and the two pages, and `routes_gen.go`
is generated from it like any other route. Nothing is special-cased.

## 2. Timestamps are RFC3339 with no fractional seconds

Go's default `time.Time` marshaling emits RFC3339Nano. Swift's `.iso8601`
decoding strategy **rejects fractional seconds**, so a default-marshaled
timestamp parses fine in JavaScript and fails on iOS — a wire defect only the
second client ever finds.

`models.Time` pins the format. A model struct must never hold a bare
`time.Time`, and a DATETIME column must be declared `timestamp`, never `string`.
`models.NullTime` exists for the nullable case so the null and non-null paths
serialize identically.

## 3. A list's `data` is never `null`

`encoding/json` marshals a nil slice held in a non-nil interface as `null`, and
`omitempty` does not strip it. A typed client decoding an array then fails on an
empty result set. Models initialize slices non-nil and `normalizeData` in
`handlers/json.go` is the second guard for hand-written handlers — the
guarantee is made structural rather than left to author discipline.

## 4. Two rate-limit buckets, with different budgets

`ClearAttempts` deletes by key and a successful login calls it, so **the key is
the isolation**. Two consequences:

- Each login endpoint gets its own **address** bucket. Sharing one lets a
  success on the bearer login erase the cookie login's failures.
- A second bucket meters the **account being attacked**. Without it, an attacker
  clears their address bucket by logging into an account they own between
  guesses — four wrong guesses, one real login, repeat, forever, with the
  limiter reporting itself healthy because the fifth attempt never arrives.

The budgets differ deliberately (5 per address, 20 per account). A per-account
bucket is also a per-account *lockout*: at threshold N, anyone who knows an
address can deny that user their login for fifteen minutes. Set equal to the
address budget that is cheap denial of service; set far above it, a lone
attacker exhausts their own address budget long before reaching it.

The account key is a SHA-256 digest of the lowercased address — the table is
written by unauthenticated callers, so a raw key would make it a log of every
address anybody probed. Lowercasing is load-bearing: without it, varying the
case bypasses the control entirely.

The window makes the limit a *rate*. A counter that only increments turns the
budget into a lifetime quota, so the bucket re-locks on its next attempt
forever — which behind a shared NAT is every user on that address.

## 5. `clientIP` needs a trusted-peer notion

Two failures that point in opposite directions, which is why fixing one does not
reveal the other:

- **Trusting a forwarding header from any peer** lets a direct caller name
  itself and mint a fresh bucket per request — unlimited guessing, limiter
  green.
- **Ignoring forwarding headers entirely** puts every caller behind a reverse
  proxy in one bucket, so five bad logins lock the whole deployment.

One trusted-peer set resolves both: an untrusted peer names only itself; a
trusted proxy's `CF-Connecting-IP`, or the **right-most** `X-Forwarded-For` entry
that is not itself a trusted hop, is believed. Right-most because a client can
prepend anything, so everything left of the first hop we trust is
attacker-authored.

## 6. CSRF verifies when a cookie is present

The scheme protects a browser riding an ambient credential. A caller with **no
cookies at all** — a native client, a webhook — has nothing for a forged
cross-site request to replay, and forcing the scheme on it only breaks it. A
bearer request is exempt for the same reason.

Safe methods are **allowlisted**, not unsafe ones denylisted: the previous
`POST || PUT || DELETE` check silently did not run on PATCH. Inverted, a method
nobody thought of is verified by default.

`csrf_token` shares the session's lifetime so the two cannot diverge on a
browser restart, which used to leave a browser holding a session and no CSRF
cookie.

## 7. Pages and endpoints are separate manifest tables

A page has no method beyond GET, no request or response body, and no deps — it
is not part of the API surface a native client consumes. Keeping the tables
apart also keeps the namespaces disjoint: `gova page` refuses `/api/`,
`gova handler` requires `/api/v1/`, so neither can shadow the other.

Resource pages are always plural (`/projects`) and the auth pages take their
singular verb (`/login`, `/register`). Because `toPlural` never returns its
input unchanged, a resource named `login` lands at `/logins` — the namespaces
cannot collide without a reserved-word list.

A page's `auth: true` wraps it in `RequirePageAuth`, a 303 rather than a JSON
401, because a browser navigation must not be answered with an error envelope.
**It is a courtesy, not a boundary**: the shell is inert and every datum on it
comes from an `/api/v1/` endpoint, so those are what must carry `auth: true`.
What the page guard buys is removing the flash of a page the visitor is about to
be bounced off.

## 8. The builder is a CLI, not an MCP server

It was an MCP server. For six commands taking string arguments, the protocol was
pure overhead: no streaming, no resources, no sampling — just request/response.
What it cost was concrete.

The **command layer had zero test coverage.** Everything below it was well
tested, but driving `handleScaffoldResource` required a JSON-RPC client, so
nothing did. As a CLI those are ordinary functions with an overridable app
directory, and there are now 18 end-to-end tests across the six commands.

It also **forced concurrency machinery that a CLI does not need.** One
long-lived server dispatching tool calls on goroutines needed an in-process
mutex *and* a cross-process flock; a template cache *and* its RWMutex. One
process per invocation needs neither — an flock alone covers every caller.

And the dependency tree went from five modules to one.

What was given up: MCP put the tool schemas in the model's context
automatically, in both harnesses. That is now a table in `CLAUDE.md`, backed by
`./gova help`. It would be worth reconsidering if the builder ever needed to run
on a different machine from the agent — that is the case MCP is actually for.

## 9. The workspace lock wraps the whole transaction

Builds are serial — one task at a time — so the lock is not there to make
subagents safe. It is there because two harness sessions can be open at once
(Claude Code and opencode share one checkout and one pair of containers), and
because it costs nothing.

Without a lock held across the full
read→upsert→write→regenerate cycle, two scaffolds read the same base manifest,
both write, and the second silently erases the first's registration — a lost
update no same-key conflict check can see, because each writer's snapshot was
already stale.

An flock on `/src/.gova-lock` covers it: LOCK_EX for mutators, LOCK_SH for
readers. Files land via temp-file + rename so a reader never sees a truncated
`.go`.

## 10. Generated code is compile-checked, not just parse-checked

Every render test stops at `parser.ParseFile`, which proves the output is
syntactically Go and nothing more. `TestRenderResourceToDir` renders a resource
into a scratch tree so it can actually be built and its own tests run.

That distinction is not academic — it caught three defects the parse tests could
not see: the handlers package needs `models.Time` where the models package needs
bare `Time`; generated test literals need the same qualification; and a
timestamp field in a test body must be RFC3339 or the handler correctly answers
422 and the test proves nothing.

## 11. The iOS client reads `api.json` off disk

`gova-ios`'s `/export:mobile` reads the committed
`$WEB_APP/src/app/api.json` directly — no running server, no MCP. That is why
`format` and `references` are in the manifest even though the web app itself
barely uses them: `format` picks the SwiftUI control, and `references` decides
whether a resource is a top-level tab or nests under its parent's detail.

It is also why there is no `GET /api/v1/_manifest` endpoint. Nothing called it.
